## 逻辑与存档复验

- 门与下一室入口按五室单向顺序连接。生成时用正式行者的 1/120 秒更新，从入口依次移动到守卫、必要踏脚台、绞盘、炉料匣和东门。模拟保留速度、翻滚冷却、站立净空和平台碰撞，检查守卫巡逻区的承重与净空。八个不可变模板按值缓存验证结果。战斗胜负另由实机路线覆盖。
- 对 0–4095 每个种子分别生成两次，得到 48 种模板组合，相同种子的记录逐项一致。此范围内均一次生成成功。单测另覆盖第二次候选成功、四次失败后退回手工路线、孤台、实体隔墙和巡逻区跨出平台。40 项 unittest 通过。[抽样统计](batch.json)
- 在独立进程通过正式模块入口运行两次种子 17，粒子初值分别为 2、3，顺序一致。种子 18 得到不同模板。默认模式死亡后从种子 2907221159 换到 1569808202，检查了磁盘的最后一局记录。原版手工、练习和交锋模式均成功打开窗口，越界种子和冲突参数以错误码 2 退出。[入口记录](entries.json)
- 另在种子 17 的门廊取消一次炉料选择、重新打开并装入赤铜刃齿，过门后在西侧绞盘室保留一阶。该流程使用临时档案，暂停选项也经实际按键操作。[装配过门](seed-17/gear.json)
- 清单覆盖 56 项资产。已解码全部 PNG，逐一核对新前景图的三格、平台顶边、门与绞盘位置。单独对 64 个种子测量生成器，清空移动验证缓存时中位耗时 19.31 ms，缓存预热后为 0.013 ms。[生成耗时](generation-time.json)

样本统计衡量布局复现和移动可达性。两条自动按键路线给出了完整战斗流程的实机证据。其余组合的逐局实战、真人首玩时长、其他硬件与本轮战斗帧耗时未验证。

## 在项目根目录复测

```powershell
.\.venv\Scripts\python.exe -m game --seed 17
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe tools\verify_stage6.py --batch
.\.venv\Scripts\python.exe tools\verify_stage6.py
.\.venv\Scripts\python.exe tools\verify_stage6.py --fallback
```

两个窗口验收命令会使用临时档案，完成后将截图和数据写回本目录。故障注入只在最后一条验收命令的进程中生效。
