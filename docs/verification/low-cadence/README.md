## 画面和输入

- **满蓄与双敌前摇。** 固定站位把行者放在 x=166，弩手放在西阶座 (330,143)，重卫放在地面 (198,94) 接刀，绞工与正式房间相同。关掉闪光，满蓄依靠刀身从 40 个逻辑像素伸至约 94 像素表现。按相同时间松开 L 之前，30 帧录到 3 个满蓄画面，60 帧录到 5 个。两敌同时前摇分别占 21 帧和 43 帧，其中张开的铜钩与青绿瞄线同屏 6 帧和 12 帧，约 0.2 秒。烈焰命中重卫造成 54 点伤害时，两名出手者仍能继续攻击。[30 帧满蓄原图](after/crossing-30-signals.png) · [收回钩前的火弧原图](after/crossing-30-swing.png)
- **正式布局。** 从入口上阶引箭，向左滚下阶座，转向阶座挥空，让箭与回钩一起逼近。该路线在蓄满后立即松手，两档各只采到一帧满蓄。原房间的钩口与瞄线出现得有先后，固定站位补验两者重叠的画面。
- **帧间轻按。** 正式入口的 30 帧改后实录中，按住 K 仅 8.06 毫秒，按下与松开均在第 324 步之后、下一次更新之前。原版把它交给第 325 步，收招预输入尚未开放。新版在挥刀时记录翻滚键按下时间与方向，按所属物理步处理。翻滚、无敌与收招时长沿用原数值。30 和 60 帧都在第 332 步起滚，绞工回钩从头顶通过，随后箭矢经过，第 420 步首刀命中，绞工从 68 血降到 52。将按键再提前约 45 毫秒，两档录像之外的 30 帧对照仍掉 18 血、未能反击。[修改前输入与事件](before/report.json) · [修改后输入与事件](after/report.json)

## 实机条件

Windows 11，RTX 5060 Laptop GPU，Arcade 3.3.3，1280×720 窗口、640×360 世界画布。震动 0、闪光 0、音量 2、粒子 1（最高 3）。每场使用独立临时存档，游戏窗口按真实时间逐帧更新和显示，键盘回调由脚本在帧间触发。录像时关闭垂直同步，以单一时钟控制画面更新。每次更新推进 2 或 4 个 120 Hz 逻辑步。先读取真实窗口帧，结束后再编码；完整 MP4 使用 640×360 采样并最近邻放大，PNG 保留窗口原分辨率。

## 复现

在发行包解压目录运行 `.\EmberCorridor.exe --seed 17 --fps 30`。按 Esc 进入设置调整闪光、粒子和震动。进入第二室，上西阶座引箭，回到绞工旁蓄力；长刀身出现后松开 L，向阶座挥刀，收刀时轻按 K，滚过后转身按 J。将 30 改为 60 即可重走。源码入口为 `.\.venv\Scripts\python.exe -m game --seed 17 --fps 30`。

自动重放使用 `.\.venv\Scripts\python.exe tools/verify_low_cadence.py --out build/cadence-replay`，可传入 `--encoder <ffmpeg.exe 的路径>` 写 MP4，省略时写 GIF。发行包可运行 `.\EmberCorridor.exe --verify-install cadence-replay --low-cadence`，使用新的输出目录。脚本核对两档窗口的血量、反击事件、采样机位、翻滚步和穿过两击的时刻。事件记录中的攻击 tick 由战斗系统在逻辑步内写入，报告中的 rolls 和 sampled_ticks 在逻辑步末采样。

本轮 Windows ZIP 在项目外的临时目录解压，移除 PATH 中的 Python 后启动 EXE。低特效五组和上一轮最高特效交叉预警均通过。低特效 EXE 与源码的事件、血量、两种来袭武器的经过时刻及采样机位一致。57 项单元测试通过。ZIP 的 SHA-256 为 `9f067df7c6f15f0a435a2850daec6d8a0279f1962c7b627ecc966069f3e22759`。[解压版低特效记录](installed-low-cadence.json) · [解压版最高特效回归](installed-flame-crossfire.json)
