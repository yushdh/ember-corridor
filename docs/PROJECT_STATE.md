## 运行与操作

在项目根目录运行 `.\.venv\Scripts\python.exe -m game`，按 Enter 开始。使用 `--skirmish` 进入原版三敌交锋，使用 `--practice` 练习移动。

A/D 移动，Space 变高跳，S+Space 下穿，K 翻滚，J 攻击，1/2 换装。潮钟线用 Q 施印、E 开门或操作机关。Esc 暂停，F1–F4 调节反馈。死亡或结算后按 R 重开。两把武器初始均持有，反馈设置在本次进程的重开之间保留。

本机为 Windows 11 build 26300、RTX 5060 Laptop、OpenGL 4.6。沿用 Python 3.12.14、Arcade 3.3.3、Pillow 11.3.0、pyglet 2.1.19。[依赖锁定](../requirements.txt)

## 潮钟线验收

退潮门廊、铆雨泵房、沉闸水道、司钟吊廊、潮钟熔庭使用独立地图、碰撞和守卫配置。潮印起手 11 步，释放时结算一次，冷却 420 步；四间厂门各回复最多 18 体力。Boss 的低扫可跳过，喷潮锁定后可移出或翻滚，进入第二阶段时先鸣钟再加快准备。25 项测试通过，资源清单覆盖 43 份项目文件及单列的本机字体。Windows 原生窗口已走通五室、暂停、鸣钟和两种重开。[逐事件记录](verification/stage4/run.json)

已知路线的自动通关约一分钟。原定 5–10 分钟体验目标尚待真人首玩测量。外放音量与手感、Windows 10、其他显卡、长时间性能和发行包均未验证。下轮进入装备与存档前，先结合实际首玩记录判断关卡是否需要扩充。

## 阶段 3 首次验收记录

- **默认交锋。** Windows 原生键盘消息驱动正常游戏窗口。弯刃三段将钩手生命从 62 打到 46、27、0；两次落锤击倒铆弩手。重卫冲锋打断过一次锤击，随后被三次有效落锤击倒。第一局清场；第二局实测滚过有效钩击，随后承受伤害直至倒下。两次 R 重置均经过正常操作入口，检查了人物血量、三敌、弩弹、无敌、缓冲和粒子状态。[逐事件记录](verification/stage3/combat.json) · [无声窗口回放](verification/stage3/combat.gif)
- **视觉与反馈。** 观察了正常视距的命中与预警截图。弯刃、锤头、火花、瞄准线和冲锋箭齿分别显示。窗口记录到 11 个合成音效各自的播放实例进入播放状态；扬声器实际听感未验证。四项暂停设置均通过原生按键调整，暂停期间战斗时钟保持不动。[轻击](verification/stage3/cut-hit.png) · [重击](verification/stage3/breaker-hit.png) · [重卫预警](verification/stage3/ram-warn.png)
- **规则与一致性。** 19 项 unittest 通过，包括原有 9 项移动测试与 10 项新增战斗测试。新增测试覆盖同次挥击去重、同种多目标、镜像连击、取消边界、重甲破势、挡墙、锁定瞄准、翻滚避伤与死亡中断。另向窗口自己的更新入口输入同一套连击；在受控的 30、60、144 Hz 更新频率下，9 个采样点的动作、生命值、位置与停顿一致。该实验没有测量实际帧率。
- **移动与像素回归。** 改动前复走阶段 2 路线；改动后从练习入口再次抵达高栈台并返回。默认战斗和练习窗口均验证 1280×720、1366×768 的居中留边及 1920×1080 的整数像素块。[移动记录](verification/stage3/movement.json) · [练习缩放记录](verification/stage3/practice-scaling.json)

## 阶段 3 交接存档

首轮命中截图显示重锤贴身时人物容易互相遮挡，检查代码后发现锤柄也使用了锤头的宽判定。现已拆分柄与头的接触范围，加入受创击退，并在重新走完的正常路线中验过。另修正了铆弩手两个姿势的手部挂点像素。一次自动验收的长按移动中途停止；验证脚本会记录丢失后重新发送的按键，最终成功记录中该列表为空。

阶段 3 交接时只有一段岸线，敌人的活动区按该段地形设置。当时留下的关卡任务现已在潮钟线实现，时长与其他未验证事项见文首的阶段 4 记录。
